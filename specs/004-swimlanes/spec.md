# Спецификация функции: Swimlane-группировка задач на доске

**Ветка функции**: `feature/004-swimlanes`

**Создано**: 2026-05-25

**Статус**: Черновик

**Ввод**: Описание пользователя: "У пользователя должна быть возможность группировать задачи на доске. Группировка выглядит, как горизонтальный контейнер (swimlane), протяжённый на все колонки. Swimlane может сворачиваться и скрывать свои задачи. Поведение swimlane — такое же, как в YouTrack и подобных системах. У свернутого swimlane видно его название. При изменении задач есть поле swimlane, которое можно задать. Это автоматически помещает задачу в нужный swimlane. Если swimlane нет, то он автоматически создаётся. На доске столько swimlane, сколько уникальных значений в соответствующих полях задач. Задачи без swimlane отображаются в дефолтном swimlane «Без категории»."

## Пользовательские сценарии и тестирование *(обязательно)*

### Пользовательская история 1 - Просмотр задач в swimlane на доске (Приоритет: P1)

Пользователь открывает доску с задачами и видит их сгруппированными по горизонтальным полосам — swimlane. Каждая swimlane протягивается через все колонки (столбцы статуса) и содержит задачи, относящиеся к одной группе. Задачи без явного указания swimlane отображаются в swimlane «Без категории».

**Почему этот приоритет**: Это базовая визуальная модель — без отображения swimlane на доске остальные функции не имеют смысла. Пользователь сразу видит группировку и может ориентироваться в задачах.

**Независимый тест**: Можно полностью протестировать открытие доски и убедиться, что задачи распределены по swimlane, а задачи без группы — в «Без категории».

**Сценарии приёмки**:

1. **Дано** на доске есть задачи с различными значениями поля swimlane, **Когда** пользователь открывает доску, **Тогда** задачи отображаются внутри горизонтальных полос, каждая полоса соответствует одному уникальному значению swimlane
2. **Дано** на доске есть задачи без указания swimlane, **Когда** пользователь открывает доску, **Тогда** эти задачи отображаются в swimlane «Без категории»
3. **Дано** на доске есть несколько задач с одинаковым swimlane в разных колонках, **Когда** пользователь открывает доску, **Тогда** swimlane протягивается через все колонки, и задачи размещаются в соответствующих колонках внутри этой swimlane

---

### Пользовательская история 2 - Сворачивание и разворачивание swimlane (Приоритет: P2)

Пользователь может свернуть любой swimlane, чтобы скрыть его задачи. Свернутый swimlane отображается в виде горизонтальной полосы с названием группы. Развернуть swimlane можно повторным нажатием. Это позволяет сфокусироваться на нужных группах задач и скрыть нерелевантные.

**Почему этот приоритет**: Сворачивание — ключевое преимущество swimlane для управления визуальным шумом на досках с большим количеством задач. Без этой функции swimlane не дают значимой пользы по сравнению с простым списком.

**Независимый тест**: Можно полностью протестировать сворачивание и разворачивание swimlane, убедившись, что задачи скрываются и появляются, а название swimlane остаётся видимым в свёрнутом состоянии.

**Сценарии приёмки**:

1. **Дано** на доске есть развёрнутый swimlane с задачами, **Когда** пользователь нажимает на элемент управления сворачиванием, **Тогда** задачи swimlane скрываются, а горизонтальная полоса показывает только название swimlane
2. **Дано** swimlane свёрнут, **Когда** пользователь нажимает на элемент управления разворачиванием, **Тогда** задачи swimlane снова отображаются
3. **Дано** пользователь свернул несколько swimlane, **Когда** пользователь обновляет страницу, **Тогда** состояние сворачивания сохраняется и swimlane остаются свёрнутыми

---

### Пользовательская история 3 - Назначение swimlane задаче через поле (Приоритет: P2)

При редактировании задачи пользователь видит поле «Swimlane» с автодополнением по существующим значениям и может задать или изменить его значение, в том числе ввести новое. При указании нового значения задача автоматически перемещается в соответствующий swimlane. Если указанное значение swimlane ещё не существует на доске, новый swimlane создаётся автоматически.

**Почему этот приоритет**: Это механизм управления группировкой — пользователь должен иметь возможность назначать и изменять принадлежность задачи к группе. Без этого swimlane не могут формироваться динамически.

**Независимый тест**: Можно полностью протестировать назначение swimlane задаче, создание нового swimlane при указании нового значения и перемещение задачи между swimlane.

**Сценарии приёмки**:

1. **Дано** пользователь редактирует задачу, **Когда** он указывает значение в поле «Swimlane», **Тогда** задача перемещается в swimlane с этим названием
2. **Дано** пользователь указывает значение swimlane, которого ещё нет на доске, **Когда** он сохраняет задачу, **Тогда** автоматически создаётся новый swimlane с указанным названием и задача помещается в него
3. **Дано** задача уже находится в swimlane «Фронтенд», **Когда** пользователь изменяет поле swimlane на «Бэкенд», **Тогда** задача перемещается из swimlane «Фронтенд» в swimlane «Бэкенд»

---

### Пользовательская история 4 - Drag-and-drop задач между swimlane (Приоритет: P3)

Пользователь может перетащить задачу из одного swimlane в другой, что автоматически обновляет поле swimlane у задачи.

**Почему этот приоритет**: Удобный способ изменить группировку без открытия формы редактирования, но не является критичным — можно изменить поле swimlane через форму.

**Независимый тест**: Можно протестировать перетаскивание задачи между swimlane и убедиться, что поле swimlane обновляется автоматически.

**Сценарии приёмки**:

1. **Дано** задача находится в swimlane «Фронтенд» в колонке «В работе», **Когда** пользователь перетаскивает задачу вертикально в swimlane «Бэкенд», **Тогда** поле swimlane задачи автоматически обновляется на «Бэкенд», а задача остаётся в той же колонке
2. **Дано** задача находится в swimlane «Без категории», **Когда** пользователь перетаскивает её в именованный swimlane, **Тогда** задача получает соответствующее значение swimlane
3. **Дано** задача находится в swimlane «Фронтенд» в колонке «В работе», **Когда** пользователь перетаскивает задачу горизонтально в колонку «Готово» в рамках того же swimlane, **Тогда** задача перемещается в колонку «Готово», поле swimlane не изменяется

---

### Граничные случаи

- Что произойдёт, если у задачи очистить поле swimlane? → Задача перемещается в swimlane «Без категории»
- Как система обрабатывает удаление единственной задачи в именованном swimlane? → Swimlane перестаёт отображаться на доске, т.к. список swimlane полностью определяется значениями поля у задач
- Что произойдёт при одинаковых названиях swimlane с разным регистром? → Swimlane регистронезависимы: «Фронтенд» и «фронтенд» — одна и та же группа. Отображается вариант, введённый первым
- Как отображается пустой swimlane (все задачи в других колонках)? → Swimlane отображается как пустая горизонтальная полоса в соответствующих колонках
- Что произойдёт, если переименовать значение swimlane у одной задачи? → Переименование влияет только на одну задачу, остальные задачи сохраняют прежнее значение
- Как обрабатывается очень длинное название swimlane? → Название обрезается с многоточием, а полное название доступно при наведении

## Требования *(обязательно)*

### Функциональные требования

- **FR-001**: Система ДОЛЖНА отображать задачи на доске, сгруппированными по горизонтальным полосам — swimlane, каждая из которых протягивается через все колонки
- **FR-002**: Система ДОЛЖНА отображать задачи без указанного swimlane в swimlane «Без категории»
- **FR-003**: Система ДОЛЖНА позволять пользователю сворачивать и разворачивать каждый swimlane независимо
- **FR-004**: Система ДОЛЖНА отображать название swimlane в свёрнутом состоянии
- **FR-005**: Система ДОЛЖНА сохранять состояние сворачивания swimlane между сеансами пользователя
- **FR-006**: Система ДОЛЖНА предоставлять поле «Swimlane» при редактировании задачи с автодополнением по существующим значениям и возможностью ввести новое значение
- **FR-007**: Система ДОЛЖНА автоматически создавать новый swimlane, когда пользователь указывает значение, которого ещё нет на доске
- **FR-008**: Система ДОЛЖНА автоматически перемещать задачу в соответствующий swimlane при изменении значения поля swimlane
- **FR-009**: Система ДОЛЖНА отображать на доске только те swimlane, для которых существует хотя бы одна задача с соответствующим значением поля swimlane. Swimlane без задач не отображаются
- **FR-010**: Система ДОЛЖНА поддерживать перетаскивание задач между swimlane (вертикально) и между колонками статуса (горизонтально) с автоматическим обновлением поля swimlane при перемещении между swimlane
- **FR-011**: Система ДОЛЖНА обрабатывать названия swimlane без учёта регистра (регистронезависимо). При совпадении названий с разным регистром отображается вариант, введённый первым
- **FR-012**: Система ДОЛЖНА отображать количество задач в каждом swimlane
- **FR-013**: Система ДОЛЖНА отображать swimlane «Без категории» всегда первым (сверху), а остальные swimlane — в алфавитном порядке по названию

### Ключевые сущности

- **Swimlane**: Виртуальная группировка задач на доске по значению поля swimlane. Не является отдельной сущностью — полностью определяется уникальными значениями этого поля у задач. Может быть свёрнута. Специальный swimlane «Без категории» содержит задачи без явной группы.
- **Задача (Task)**: Сущность с полем «swimlane» — текстовым значением, определяющим принадлежность к группе. При отсутствии значения задача относится к «Без категории».

## Критерии успеха *(обязательно)*

### Измеримые результаты

- **SC-001**: Пользователи видят задачи сгруппированными по swimlane не более чем за 2 секунды при открытии доски с 200 задачами
- **SC-002**: Сворачивание и разворачивание swimlane происходит мгновенно, без перезагрузки страницы
- **SC-003**: 90% пользователей могут назначить swimlane задаче с первой попытки без дополнительного обучения
- **SC-004**: Изменение swimlane у задачи отражается на доске не более чем через 2 секунды
- **SC-005**: Новые swimlane создаются автоматически при указании нового значения, без дополнительных действий от пользователя

### Сессия 2026-05-25

- Q: Как должен работать drag-and-drop — только горизонтально или также вертикально между swimlane? → A: Полноценный drag-and-drop в обоих направлениях — вертикально между swimlane и горизонтально между колонками. При перетаскивании между swimlane автоматически обновляется поле swimlane.
- Q: Удаляется ли пустой swimlane с доски или сохраняется в системе? → A: Swimlane не является отдельной сущностью — список swimlane полностью определяется уникальными значениями поля swimlane у задач. Если нет ни одной задачи с данным значением swimlane, соответствующий swimlane не отображается на доске. Аналогично списку исполнителей.
- Q: Какой тип ввода должно иметь поле «Swimlane»? → A: Автодополнение по существующим значениям с возможностью ввести новое значение.
- Q: В каком регистре отображается название swimlane при регистронезависимой обработке? → A: В том виде, в котором значение впервые введено — первое вхождение определяет отображаемый вид.
- Q: В каком порядке swimlane отображаются на доске? → A: Дефолтный swimlane «Без категории» — всегда сверху, остальные — по алфавиту.

## Допущения

- Пользователи работают с досками, на которых может быть от нескольких до сотен задач
- Swimlane — это виртуальная группировка, полностью определяемая значениями поля swimlane у задач. Нет отдельного управления списком swimlane — они появляются и исчезают по мере изменения значений у задач (аналогично списку исполнителей). В первой версии у swimlane нет собственных настроек (цвет, иконка и т.д.)
- Состояние сворачивания swimlane сохраняется локально в браузере пользователя
- Порядок swimlane на доске фиксирован: «Без категории» — всегда сверху, остальные — по алфавиту. Пользовательская перестановка не входит в данную функцию
- Drag-and-drop поддерживается в обоих направлениях: вертикально между swimlane и горизонтально между колонками статуса
