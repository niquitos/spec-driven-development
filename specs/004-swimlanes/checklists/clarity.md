# Чек-лист требований: Ясность и полнота — Swimlane

**Назначение**: Проверка спецификации на неоднозначности, пропуски и неясные формулировки перед переходом к планированию
**Создано**: 2026-05-25
**Функция**: [spec.md](../spec.md)
**Глубина**: Стандартная (~25-30 элементов)
**Фокус**: Неоднозначности/ясность, Полнота/пропуски
**Аудитория**: Автор (самопроверка)

## Неоднозначности и ясность

- [x] CHK001 Определено ли, какой тип ввода представляет поле «Swimlane» — произвольный текст, выпадающий список существующих значений или автодополнение? [Ясность, Spec §FR-006] — **Автодополнение по существующим значениям с возможностью ввода нового (free-text)**. Уточнено в FR-006 и research §5.
- [x] CHK002 Куда именно помещается новый swimlane при автоматическом создании — в начало, конец или по алфавиту? [Ясность, Spec §FR-007] — **«Без категории» всегда первый, остальные — по алфавиту (case-insensitive)**. Уточнено в FR-013 и research §6.
- [x] CHK003 Что означает «мгновенно» в SC-002 — есть ли конкретный порог в миллисекундах, или это достаточно уточнить как «без перезагрузки страницы»? [Ясность, Spec §SC-002] — **<100мс (re-render), визуальная анимация 200мс**. Уточнено в plan (цели производительности).
- [x] CHK004 Какой именно элемент управления используется для сворачивания/разворачивания swimlane — кнопка, иконка, клик по заголовку? [Ясность, Spec §FR-003] — **Кнопка toggle с role="button" и ARIA-атрибутами**. Уточнено в research §9 и data-model (визуальное представление).
- [x] CHK005 Если swimlane регистронезависимы (FR-011), то в каком регистре отображается название — как ввёл первый пользователь, как ввёл последний, или всегда с заглавной буквы? [Ясность, Spec §FR-011] — **Отображается вариант, введённый первым (first occurrence)**. Уточнено в FR-011 и research §2.
- [x] CHK006 В граничном случае указано, что название удалённого swimlane «сохраняется в системе для возможного повторного использования» — противоречит ли это FR-009, который требует «удалять пустой swimlane с доски»? Разъяснена ли разница между удалением с доски и сохранением в системе? [Согласованность, Spec §FR-009] — **Нет противоречия: swimlane исчезает с доски (FR-009), но stale-записи в localStorage не вызывают проблем (research §4, CHK033)**.
- [x] CHK007 Допущение «Drag-and-drop поддерживается только в горизонтальном направлении» противоречит пользовательской истории US-4, где задача перетаскивается из одного swimlane в другой (вертикальное перемещение). Разъяснено ли, как именно работает вертикальный drag-and-drop между swimlane? [Согласованность, Spec §US-4 vs Допущения] — **Допущение было уточнено в сессии 2026-05-25: полноценный drag-and-drop в обоих направлениях**. Research §3 описывает составные droppableId.
- [x] CHK008 Определено ли, что происходит при одновременном изменении swimlane несколькими пользователями — последнее изменение побеждает, или есть механизм разрешения конфликтов? [Ясность, Gap] — **Last-write-wins через optimistic update**. Нет системы аутентификации, multi-user конфликты за рамками MVP.
- [x] CHK009 FR-012 требует отображать количество задач в каждом swimlane, но ни один сценарий приёмки не проверяет это требование. Следует ли добавить сценарий для FR-012 или это требование избыточно? [Полнота, Spec §FR-012] — **FR-012 покрывается реализацией SwimlaneHeader (T025: «заголовок swimlane с названием, количеством задач»)**. Отдельный сценарий приёмки не нужен — визуальная модель data-model явно показывает "(3)", "(12)".
- [x] CHK010 Определён ли порядок отображения swimlane на доске — по алфавиту, по дате создания, по количеству задач, или пользователь может менять порядок? [Gap] — **«Без категории» — всегда первый, остальные — по алфавиту (case-insensitive)**. FR-013 и research §6.
- [x] CHK011 Определено ли начальное состояние swimlane при первом открытии доски — все развёрнуты, все свёрнуты, или есть логика по умолчанию? [Gap, Spec §FR-003] — **Все swimlane развёрнуты (localStorage пустой при первом визите)**. При повторном визите — состояние восстанавливается из localStorage.
- [x] CHK012 Указано ли, что происходит с состоянием сворачивания при изменении набора swimlane (добавление/удаление задачи создаёт новый swimlane)? Сохраняются ли свёрнутые состояния новых swimlane? [Gap, Spec §FR-005] — **Новые swimlane появляются развёрнутыми (нет записи в localStorage)**. Удалённые swimlane оставляют stale-запись, которая игнорируется (research §4, CHK033).
- [x] CHK013 Описано ли поведение доски, когда все задачи находятся в swimlane «Без категории» (т.е. нет ни одного именованного swimlane)? [Gap] — **«Без категории» — единственный swimlane на доске, отображается первым**. Research §6 (CHK003).
- [x] CHK014 Определена ли валидация для названия swimlane — можно ли указать пустую строку, пробелы, спецсимволы, очень длинные имена? [Gap, Spec §FR-006] — **Maxlength 100 (frontend — обрезка ввода, backend — 400 Bad Request)**. Пробельные строки → null. Research §11, data-model.
- [x] CHK015 Указано ли ограничение на максимальное количество swimlane на одной доске? Что происходит при очень большом числе уникальных значений? [Gap] — **Нет явного ограничения. Объём ограничен ~20 swimlane при 200 задачах (plan constraints)**. Производительность проверена для этого масштаба.
- [x] CHK016 Описано ли, что происходит с состоянием сворачивания при смене пользователя или при работе с одной доской разными пользователями — является ли состояние сворачивания персональным? [Gap, Spec §FR-005] — **Персональное для браузера (localStorage), не синхронизируется между устройствами**. При смене браузера — все swimlane развёрнуты. Plan constraints.
- [x] CHK017 Указано ли поведение при drag-and-drop задачи в swimlane «Без категории» — очищается ли поле swimlane у задачи? [Gap, Spec §US-4] — **Да, task.swimlane = null**. Research §3 (CHK025): «Обратное перемещение — устанавливает task.swimlane = null».
- [x] CHK018 Определено ли, что происходит при drag-and-drop, если целевой swimlane ещё не существует — создаётся ли он автоматически (как при вводе через поле)? [Gap, Spec §US-4 vs §FR-007] — **Drag-and-drop перемещает между существующими swimlane. Новые swimlane создаются только через поле (US-3)**. Это заложено в дизайн.
- [x] CHK019 Описаны ли требования к доступности (accessibility) — навигация по swimlane с клавиатуры, скринридеры, ARIA-атрибуты? [Gap] — **Да: role="button", aria-expanded, aria-controls, aria-label на toggle; Enter/Space для клавиатуры; prefers-reduced-motion**. Research §9.
- [x] CHK020 Указано ли, что происходит при удалении swimlane через удаление всех его задач — уведомляется ли пользователь, что swimlane исчезнет? [Gap, Spec §FR-009] — **Уведомление не нужно: swimlane — виртуальная сущность, автоматически исчезает при удалении последней задачи**. Optimistic update обеспечивает мгновенную визуальную обратную связь.
- [x] CHK021 Определено ли поведение при пустой доске (нет задач вообще) — отображается ли swimlane «Без категории» как пустой? [Gap] — **При пустой доске swimlane не отображаются**. «Без категории» появляется только когда есть задачи без swimlane. FR-009: только swimlane с задачами отображаются.
- [x] CHK022 Все ли функциональные требования (FR-001–FR-012) покрыты хотя бы одним сценарием приёмки? [Полнота, трассировка FR→сценарии] — **Все FR покрыты сценариями приёмки или явными решениями в плане**. FR-012 (количество задач) покрывается через SwimlaneHeader.
- [x] CHK023 Соответствуют ли допущения функциональным требованиям — например, допущение «нет отдельного управления списком swimlane» согласуется ли с FR-007 (автоматическое создание) и FR-009 (автоматическое удаление)? [Согласованность, Допущения vs FR] — **Согласуются: виртуальная сущность автоматически создаётся (FR-007) и удаляется (FR-009)**. Допущение о «нет отдельного управления» подтверждено спецификацией.
- [x] CHK024 SC-003 заявляет «90% пользователей могут назначить swimlane задаче с первой попытки» — определён ли метод измерения этого критерия (юзабилити-тест, аналитика, опрос)? [Ясность, Spec §SC-003] — **Эвристическая оценка UX: автодополнение + free-text + placeholder-подсказка + мгновенная обратная связь**. Формальное usability-тестирование не входит в план. Plan (цели производительности).
- [x] CHK025 SC-001 и SC-004 содержат конкретные временные пороги (2 секунды), но SC-002 использует «мгновенно» — следует ли заменить на измеримый порог или уточнить, что «мгновенно» означает «без серверного запроса»? [Измеримость, Spec §SC-002] — **Уточнено: <100мс re-render, анимация 200мс CSS transition**. Чисто frontend-операция без серверного запроса. Plan (цели производительности).

- [x] CHK011 Определено ли начальное состояние swimlane при первом открытии доски — все развёрнуты, все свёрнуты, или есть логика по умолчанию? [Gap, Spec §FR-003] — **Все развёрнуты (пустой localStorage)**. Research §4.
- [x] CHK012 Указано ли, что происходит с состоянием сворачивания при изменении набора swimlane (добавление/удаление задачи создаёт новый swimlane)? Сохраняются ли свёрнутые состояния новых swimlane? [Gap, Spec §FR-005] — **Новые — развёрнуты, удалённые — stale-запись игнорируется**. Research §4 (CHK033).
- [x] CHK013 Описано ли поведение доски, когда все задачи находятся в swimlane «Без категории» (т.е. нет ни одного именованного swimlane)? [Gap] — **«Без категории» — единственный swimlane**. Research §6 (CHK003).
- [x] CHK014 Определена ли валидация для названия swimlane — можно ли указать пустую строку, пробелы, спецсимволы, очень длинные имена? [Gap, Spec §FR-006] — **Maxlength 100, whitespace → null**. Research §11, data-model.

- [x] CHK016 Описано ли, что происходит с состоянием сворачивания при смене пользователя или при работе с одной доской разными пользователями — является ли состояние сворачивания персональным? [Gap, Spec §FR-005] — **Персональное для браузера (localStorage)**. Plan constraints.

- [x] CHK018 Определено ли, что происходит при drag-and-drop, если целевой swimlane ещё не существует — создаётся ли он автоматически (как при вводе через поле)? [Gap, Spec §US-4 vs §FR-007] — **Нет, drag-and-drop только между существующими swimlane**. Новые создаются через поле (US-3).
- [x] CHK019 Описаны ли требования к доступности (accessibility) — навигация по swimlane с клавиатуры, скринридеры, ARIA-атрибуты? [Gap] — **Да, research §9**.
- [x] CHK020 Указано ли, что происходит при удалении swimlane через удаление всех его задач — уведомляется ли пользователь, что swimlane исчезнет? [Gap, Spec §FR-009] — **Уведомление не нужно (виртуальная сущность)**. Optimistic update обеспечивает визуальную обратную связь.
