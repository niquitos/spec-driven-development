# Feature Specification: Kanban Calendar Board

**Feature Branch**: `001-kanban-calendar`  
**Created**: 2026-05-09  
**Status**: Draft  
**Input**: Проект для отслеживания задач. Похож на канбан доску. Имеются колонки "Новые", "В процессе", "Сделаны". Однако, вместо спринтов - обычные даты как в каледаре. В шапке показывается выбранная дата (по умолчанию - текущая). Доска показывает задачи только для выбранной даты. Слева и справа от даты - кнопки навигации на один день назад или вперед. Также есть date-picker. Задачи можно создавать, нажимая на "+" вверху любой колонки. Задача создается в соответствующем статусе, имеет выбранную дату. Пользователь может задать название, описание и свою дату при создании задачи. Карточка задачи содержит иконки карандаш и урна. При клике на карандаш задачу можно изменить. При клике на урну - можно удалить. Перед удалением задачи - дополнительно спросить. Задачи можно выбирать (есть галочка) для массовых операций. При редактировании дату задачи можно изменить. Задачи можно перетаскивать между колонками. Задачи можно перетаскивать вертикально внутри одной колонки.

## User Scenarios & Testing

### User Story 1 - Просмотр задач на дату (Priority: P1)

Пользователь открывает приложение и видит канбан-доску с задачами на текущую дату. Задачи распределены по трём колонкам: "Новые", "В процессе", "Сделаны".

**Why this priority**: Базовая функция просмотра — основа всего приложения. Без неё невозможна работа с задачами.

**Independent Test**: Пользователь может открыть приложение, выбрать дату и увидеть все задачи этой даты в правильных колонках.

**Acceptance Scenarios**:

1. **Given** пользователь открыл приложение, **When** загружается доска, **Then** отображается текущая дата и задачи этой даты
2. **Given** пользователь выбрал дату в прошлом, **When** отображается доска, **Then** показываются задачи выбранной даты
3. **Given** задач на дату нет, **When** доска загружена, **Then** колонки пустые, но функциональны

---

### User Story 2 - Навигация по датам (Priority: P1)

Пользователь может перемещаться между датами с помощью кнопок "назад/вперёд" и date-picker.

**Why this priority**: Навигация необходима для просмотра и управления задачами в разные дни.

**Independent Test**: Пользователь может кликнуть на кнопки навигации и выбрать дату через picker.

**Acceptance Scenarios**:

1. **Given** отображается дата 15 мая, **When** пользователь нажимает "назад", **Then** отображается 14 мая
2. **Given** отображается дата 15 мая, **When** пользователь нажимает "вперёд", **Then** отображается 16 мая
3. **Given** пользователь открыл date-picker, **When** выбрал дату, **Then** доска обновляется для выбранной даты

---

### User Story 3 - Создание задачи (Priority: P1) 🎯 MVP

Пользователь создаёт задачу, нажимая "+" вверху колонки. Задача создаётся в статусе этой колонки с выбранной датой.

**Why this priority**: Создание задач — основная функция приложения. Без создания задач приложение бесполезно.

**Independent Test**: Пользователь может создать задачу с названием и описанием в любой колонке.

**Acceptance Scenarios**:

1. **Given** пользователь в колонке "Новые", **When** нажимает "+" и вводит название, **Then** задача появляется в колонке "Новые"
2. **Given** пользователь создаёт задачу, **When** вводит название и описание, **Then** задача сохраняется с обоими полями
3. **Given** пользователь создаёт задачу, **When** выбирает другую дату, **Then** задача создаётся с выбранной датой
4. **Given** задача создана, **When** пользователь возвращается к дате создания, **Then** задача отображается в правильной колонке

---

### User Story 4 - Редактирование задачи (Priority: P2)

Пользователь может редактировать задачу через иконку карандаша: изменить название, описание и дату.

**Why this priority**: Позволяет корректировать задачи, но не блокирует базовую работу.

**Independent Test**: Пользователь открывает редактирование, меняет поля и сохраняет.

**Acceptance Scenarios**:

1. **Given** задача существует, **When** пользователь кликает на карандаш, **Then** открывается форма редактирования
2. **Given** форма редактирования открыта, **When** пользователь меняет название и сохраняет, **Then** изменения отображаются
3. **Given** форма редактирования открыта, **When** пользователь меняет дату, **Then** задача перемещается на новую дату
4. **Given** форма редактирования открыта, **When** пользователь отменяет, **Then** изменения не сохраняются

---

### User Story 5 - Удаление задачи (Priority: P2)

Пользователь может удалить задачу через иконку урны с подтверждением.

**Why this priority**: Важная функция управления, но не блокирует основную работу.

**Independent Test**: Пользователь кликает на урну, подтверждает, задача исчезает.

**Acceptance Scenarios**:

1. **Given** задача существует, **When** пользователь кликает на урну, **Then** появляется диалог подтверждения
2. **Given** диалог подтверждения открыт, **When** пользователь подтверждает, **Then** задача удаляется
3. **Given** диалог подтверждения открыт, **When** пользователь отменяет, **Then** задача остаётся

---

### User Story 6 - Перетаскивание задач (Priority: P2)

Пользователь может перетаскивать задачи между колонками (смена статуса) и вертикально внутри колонки (изменение порядка).

**Why this priority**: Улучшает UX работы с доской, но не критично для базовой функциональности.

**Independent Test**: Пользователь может drag-n-drop задачу в другую колонку и изменить порядок.

**Acceptance Scenarios**:

1. **Given** задача в колонке "Новые", **When** пользователь перетаскивает в "В процессе", **Then** статус задачи меняется
2. **Given** задачи в колонке, **When** пользователь меняет порядок, **Then** новый порядок сохраняется
3. **Given** задача перетаскивается, **When** пользователь отпускает в другой колонке, **Then** задача отображается в новой колонке

---

### User Story 7 - Массовые операции (Priority: P3)

Пользователь может выбирать несколько задач галочками и выполнять массовые операции.

**Why this priority**: Дополнительное удобство для работы с множеством задач.

**Independent Test**: Пользователь выбирает задачи галочками, видит панель массовых операций.

**Acceptance Scenarios**:

1. **Given** задачи на доске, **When** пользователь выбирает галочками несколько, **Then** отображается панель массовых операций
2. **Given** выбраны задачи, **When** пользователь выполняет массовую операцию, **Then** операция применяется ко всем выбранным

---

### Edge Cases

- Что происходит при перетаскивании задачи на дату, где она уже существует?
- Как система обрабатывает отключение интернета при сохранении задачи?
- Что происходит при удалении задачи, которая уже выбрана для массовой операции?
- Как отображаются задачи с пустым описанием?

## Requirements

### Functional Requirements

- **FR-001**: Система MUST отображать канбан-доску с тремя колонками: "Новые", "В процессе", "Сделаны"
- **FR-002**: Система MUST показывать выбранную дату в шапке приложения
- **FR-003**: Система MUST отображать задачи только для выбранной даты
- **FR-004**: Пользователь MUST иметь возможность перемещаться на день назад/вперёд кнопками навигации
- **FR-005**: Пользователь MUST иметь возможность выбрать дату через date-picker
- **FR-006**: Пользователь MUST иметь возможность создать задачу нажатием "+" в любой колонке
- **FR-007**: Система MUST присваивать новой задаче статус колонки, в которой она создана
- **FR-008**: Пользователь MUST иметь возможность задать название, описание и дату при создании задачи
- **FR-009**: Пользователь MUST иметь возможность редактировать задачу через иконку карандаша
- **FR-010**: Пользователь MUST иметь возможность удалить задачу через иконку урны с подтверждением
- **FR-011**: Пользователь MUST иметь возможность выбирать задачи галочками для массовых операций
- **FR-012**: Пользователь MUST иметь возможность перетаскивать задачи между колонками
- **FR-013**: Пользователь MUST иметь возможность перетаскивать задачи вертикально внутри колонки
- **FR-014**: При изменении даты задачи система MUST переместить задачу на новую дату

### Key Entities

- **Задача**: Единица работы с названием, описанием, статусом, датой и порядком в колонке
- **Колонка**: Контейнер для задач с определённым статусом ("Новые", "В процессе", "Сделаны")
- **Дата**: Календарный день, для которого отображаются задачи

## Success Criteria

### Measurable Outcomes

- **SC-001**: Пользователь может создать задачу менее чем за 30 секунд
- **SC-002**: Переключение между датами происходит менее чем за 1 секунду
- **SC-003**: 95% пользователей успешно перетаскивают задачу в нужную колонку с первой попытки
- **SC-004**: Пользователь может найти и открыть задачу на выбранную дату менее чем за 10 секунд

## Assumptions

- Пользователи работают с приложением на десктопе или планшете (поддержка drag-n-drop)
- Задачи хранятся локально или синхронизируются с облаком (не влияет на UX)
- Поддерживается один пользователь (нет совместного доступа к доске)
- Дата по умолчанию — текущая дата устройства пользователя
- Массовые операции включают удаление и перемещение (детали в планировании)
