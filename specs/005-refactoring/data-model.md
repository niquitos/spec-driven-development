## Существующие сущности

### TaskEntity (без изменений)

Модель данных задач не изменяется. Существующая структура достаточна для PATCH-семантики.

| Поле | Тип | Обязательное | Описание |
|------|-----|-------------|----------|
| Id | int | Да | Первичный ключ |
| Title | string | Да | Название задачи |
| Description | string? | Нет | Описание задачи |
| Status | TaskStatus | Да | Статус (New=0, InProgress=1, Done=2) |
| Date | DateTime | Да | Дата задачи |
| Order | int | Да | Порядок в колонке |
| CreatedAt | DateTime | Да | Дата создания |
| UpdatedAt | DateTime | Да | Дата последнего обновления |
| Assignee | string? | Нет | Исполнитель |
| Swimlane | string? | Нет | Название свимлейна |

## Новые сущности

### PatchTaskCommand (DTO)

Частичное обновление задачи. Только переданные (не-null) поля обновляются. Null означает «не изменять». Для очистки необязательного строкового поля передаётся пустая строка `""`, которая нормализуется в `null` хэндлером.

| Поле | Тип | Обязательное | Null-семантика | Описание |
|------|-----|-------------|----------------|----------|
| Id | int | Да | — | Идентификатор задачи |
| Title | string? | Нет | null = не изменять | Новое название |
| Description | string? | Нет | null = не изменять, "" = очистить | Новое описание |
| Status | TaskStatus? | Нет | null = не изменять | Новый статус |
| Date | DateTime? | Нет | null = не изменять | Новая дата |
| Order | int? | Нет | null = не изменять | Новый порядок |
| Assignee | string? | Нет | null = не изменять, "" = очистить | Новый исполнитель |
| Swimlane | string? | Нет | null = не изменять, "" = очистить | Новый свимлейн |

**Правила нормализации** (в хэндлере):
- `Assignee`: пустая строка или пробелы → `null` (очистить)
- `Swimlane`: пустая строка или пробелы → `null` (очистить)
- `Description`: пустая строка → `null` (очистить)
- Строковые значения с пробелами по краям → `Trim()`
- `Status` или `Order` изменён → пересчёт порядка задач в колонке (существующая логика `RecalculateOrders`)

### PatchTaskResponse (опционально)

Если фронтенду нужно обновлённое состояние задачи после PATCH:

| Поле | Тип | Описание |
|------|-----|----------|
| (пустое) | — | Возвращает 204 No Content, как PUT |

**Решение**: PATCH возвращает 204 No Content, аналогично PUT. Фронтенд использует optimistic update и не нуждается в теле ответа.

## Переход состояний

### Обновление задачи — до и после

```
ДО (только PUT):
  PUT /api/tasks/{id} → все поля обязательны → потеря данных при пропуске поля

ПОСЛЕ (PUT + PATCH):
  PUT   /api/tasks/{id} → все поля → форма редактирования (полная замена)
  PATCH /api/tasks/{id} → только изменённые поля → перетаскивание, частичные обновления
```

### Семантика null в PATCH

| Поле | JSON в запросе | Значение |
|------|---------------|----------|
| swimlane отсутствует | `{ "status": "InProgress" }` | Не изменять свимлейн |
| swimlane: null | `{ "swimlane": null }` | Очистить свимлейн |
| swimlane: "" | `{ "swimlane": "" }` | Очистить свимлейн (нормализуется в null) |
| swimlane: "Фронтенд" | `{ "swimlane": "Фронтенд" }` | Установить свимлейн |
| title: "Новое" | `{ "title": "Новое" }` | Изменить название |
| title отсутствует | `{ "status": "InProgress" }` | Не изменять название |

## Валидация

### Существующая валидация (CreateTask)

- Title: обязательное, max 200 символов
- Description: max 2000 символов
- Assignee: max 100 символов
- Swimlane: max 100 символов

### Новая валидация (PatchTask)

- Если Title передан: обязательное, max 200 символов
- Если Description передан: max 2000 символов
- Если Assignee передан: max 100 символов
- Если Swimlane передан: max 100 символов
- Id: обязательное, > 0
