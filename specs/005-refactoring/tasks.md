# Задачи: Рефакторинг — исправление потери данных и повышение качества

**Ввод**: Проектные документы из `/specs/005-refactoring/`

**Предварительные требования**: plan.md, spec.md, research.md, data-model.md, contracts/patch-task.md, quickstart.md

**Тесты**: Конституция проекта требует TDD — тесты пишутся ДО реализации. Задачи на тесты включены в каждую фазу.

**Организация**: Задачи сгруппированы по пользовательским историям для обеспечения независимой реализации и тестирования каждой истории.

**Коммит после каждой фазы**: После завершения каждой фазы проект должен собираться (`dotnet build`, `npm run build`), все тесты должны проходить (`dotnet test`, `npm run test`), и изменения должны быть закоммичены.

## Формат: `[ID] [P?] [История] Описание`

- **[P]**: Может выполняться параллельно (разные файлы, нет зависимостей)
- **[История]**: К какой пользовательской истории относится задача (US1, US2, US3, US4)

## Соглашения о путях

- **Backend**: `backend/src/` (исходный код), `backend/tests/` (тесты)
- **Frontend**: `frontend/src/` (исходный код), `frontend/tests/` (тесты)

## Стратегия реализации

### MVP (Фазы 1 + 2 + 3)

1. Завершить Фазу 1: PATCH-эндпоинт → протестировать
2. Завершить Фазу 2: moveTask с PATCH → протестировать перетаскивание
3. Завершить Фазу 3: SwimlaneCombobox fix → протестировать формы
4. **СТОП И ВАЛИДАЦИЯ**: Перетаскивание сохраняет свимлейн, формы предзаполнены

### Полная доставка (+ Фазы 4, 5, 6)

5. Завершить Фазу 4: Расширенное PATCH-покрытие
6. Завершить Фазу 5: Регрессионные тесты
7. Завершить Фазу 6: Доработка

## Заметки

- Конституция требует TDD: тесты пишутся ДО реализации
- Каждый коммит после фазы должен проходить `dotnet build`, `dotnet test`, `npm run build`, `npm run test`
