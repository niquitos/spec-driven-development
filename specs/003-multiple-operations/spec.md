# Спецификация функции: Массовые операции над задачами

**Ветка функции**: `feature/003-multiple-operations`

**Создано**: 2026-05-23

**Статус**: Черновик

**Ввод**: Описание пользователя: "У пользователя должна быть возможность делать массовые операции над задачами. Доступные операции: 1. удаление, 2. изменение даты. Также нужна кнопка для переноса всех несделанных задач на следующий день. Без диалоговых окон и подтверждений — все несделанные задачи переезжают."

## Clarifications

### Session 2026-05-23

- Q: На какие задачи действует кнопка «Перенести на завтра»? → A: Действует на все невыполненные задачи независимо от их текущей даты, перенося их на завтра. Кнопка доступна всегда.
- Q: Нужна ли функция «Выбрать все»? → A: Нет, пользователь выделяет каждую задачу вручную (checkbox/клик по каждой). Функции «Выбрать все» не предусмотрено.
- Q: Как пользователь указывает новую дату при массовом изменении? → A: Выбор конкретной даты через календарь/пикер даты — пользователь выбирает точную целевую дату.
- Q: Что происходит с выделением задач после массовой операции? → A: Выделение снимается со всех задач после выполнения любой массовой операции.
- Q: Где расположены кнопки массовых действий? → A: Панель действий появляется (или становится активной) только при наличии выделенных задач и скрывается, когда ничего не выделено.

## Пользовательские сценарии и тестирование

### Пользовательская история 1 - Массовое удаление задач (Приоритет: P1)

Пользователь выбирает несколько задач в списке и удаляет их все разом. Это основная массовая операция, которая экономит время при очистке списка задач.

**Почему этот приоритет**: Удаление — самая частая массовая операция в трекерах задач. Без неё пользователю приходится удалять задачи по одной, что при большом количестве невыполненных задач становится утомительным.

**Независимый тест**: Можно полностью протестировать выбор нескольких задач и их удаление — это уже приносит ценность, позволяя очистить список от ненужных задач за одно действие.

**Сценарии приёмки**:

1. **Дано** список задач с несколькими задачами, **Когда** пользователь выбирает две или более задач и нажимает кнопку удаления, **Тогда** все выбранные задачи удаляются из списка
2. **Дано** список задач, **Когда** пользователь выбирает одну задачу и нажимает кнопку удаления, **Тогда** выбранная задача удаляется из списка
3. **Дано** список задач с выбором нескольких задач, **Когда** пользователь снимает выделение с одной из выбранных задач и нажимает кнопку удаления, **Тогда** удаляются только остающиеся выделенными задачи

---

### Пользовательская история 2 - Массовое изменение даты задач (Приоритет: P2)

Пользователь выбирает несколько задач и изменяет их дату на одну и ту же. Полезно при переносе группы задач на другой день.

**Почему этот приоритет**: Изменение даты — вторая по востребованности операция, особенно при планировании. Однако она зависит от наличия механизма выбора задач, который реализуется в P1.

**Независимый тест**: Можно протестировать выбор задач и изменение их даты — это приносит ценность при перепланировании задач на другой день.

**Сценарии приёмки**:

1. **Дано** список задач с несколькими выбранными задачами, **Когда** пользователь выбирает конкретную дату через пикер даты для них, **Тогда** дата всех выбранных задач обновляется на указанную
2. **Дано** список задач с выбранной одной задачей, **Когда** пользователь изменяет её дату через массовую операцию, **Тогда** дата этой задачи обновляется

---

### Пользовательская история 3 - Перенос всех несделанных задач на следующий день (Приоритет: P3)

Пользователь нажимает одну кнопку, и все невыполненные задачи независимо от их текущей даты переносятся на завтрашний день. Без диалогов и подтверждений — мгновенное действие. Кнопка доступна всегда, а не только при просмотре определённого дня.

**Почему этот приоритет**: Это специализированная удобная операция, которая является частным случаем массового изменения даты, но значительно ускоряет повседневную рутину. Зависит от механизма определения «несделанных» задач.

**Независимый тест**: Можно протестировать перенос всех несделанных задач одним нажатием — это приносит очевидную ценность для ежедневного использования трекера.

**Сценарии приёмки**:

1. **Дано** задачи на разных датах, часть из которых выполнена, а часть — нет, **Когда** пользователь нажимает кнопку «Перенести на завтра», **Тогда** все невыполненные задачи (независимо от их текущей даты) переносятся на завтрашний день, выполненные остаются на своих датах
2. **Дано** задачи, все из которых выполнены, **Когда** пользователь нажимает кнопку «Перенести на завтра», **Тогда** отображается сообщение «Нет задач для переноса» и ни одна задача не изменяется
3. **Дано** задачи, где ни одна задача не выполнена, **Когда** пользователь нажимает кнопку «Перенести на завтра», **Тогда** все невыполненные задачи переносятся на завтрашний день

---

### Граничные случаи

- **Все задачи удалены**: Если пользователь удаляет все задачи через массовую операцию, система отображает пустое состояние списка задач (FR-023)
- **Нет невыполненных задач для переноса**: Если при нажатии «Перенести на завтра» нет ни одной невыполненной задачи, система отображает сообщение «Нет задач для переноса» и не вносит изменений (FR-020)
- **Задачи с разных дат**: При массовом изменении даты все выбранные задачи (независимо от их исходной даты) получают одну и ту же целевую дату, выбранную через пикер (FR-009)
- **Повторное нажатие «Перенести на завтра»**: Система предотвращает повторную отправку запроса при быстром повторном нажатии (debounce, FR-021). Каждое корректное нажатие обрабатывается идемпотентно — все невыполненные задачи устанавливаются на завтрашнюю дату
- **Конкурентное изменение**: Массовые операции выполняются атомарно на сервере (FR-014). Если задача была изменена в момент выполнения массовой операции, сервер обрабатывает её в состоянии на момент выполнения

## Требования

### Функциональные требования

- **FR-001**: Система ДОЛЖНА предоставлять возможность выбора нескольких задач одновременно путём ручного выделения каждой задачи (checkbox или клик); функция «Выбрать все» не предусмотрена
- **FR-002**: Система ДОЛЖНА предоставлять операцию массового удаления для всех выбранных задач
- **FR-003**: Система ДОЛЖНА предоставлять операцию массового изменения даты для всех выбранных задач через выбор конкретной целевой даты (пикер даты)
- **FR-004**: Система ДОЛЖНА предоставлять кнопку «Перенести на завтра», которая переносит все невыполненные задачи (независимо от их текущей даты) на завтрашний день
- **FR-005**: Все массовые операции (удаление, изменение даты, перенос на завтра) ДОЛЖНЫ выполняться без диалоговых окон и подтверждений
- **FR-006**: Система ДОЛЖНА визуально отображать, какие задачи выбраны для массовой операции
- **FR-012**: Система ДОЛЖНА отображать панель массовых действий только при наличии выделенных задач; панель ДОЛЖНА немедленно появляться при выделении первой задачи и немедленно скрываться при снятии последнего выделения
- **FR-013**: При ошибке API во время массовой операции система ДОЛЖНА отображать сообщение об ошибке и сохранять текущее состояние задач без изменений
- **FR-014**: Массовые операции ДОЛЖНЫ выполняться атомарно — либо все задачи обрабатываются успешно, либо ни одна не изменяется
- **FR-015**: Отмена выбора даты в пикере (закрытие без выбора) НЕ ДОЛЖНА применять изменения к выбранным задачам
- **FR-016**: При массовом изменении даты порядок задач в целевом дне ДОЛЖЕН сохраняться
- **FR-017**: После выполнения любой массовой операции система ДОЛЖНА отображать обратную связь — количество затронутых задач для удаления и изменения даты, количество перенесённых задач для «Перенести на завтра»
- **FR-018**: Выбранные задачи ДОЛЖНЫ быть визуально отмечены чекбоксом и изменением фона или рамки, чётко отличающим их от невыбранных
- **FR-019**: Операция «Перенести на завтра» действует независимо от выделения задач — она затрагивает ВСЕ невыполненные задачи (Status ≠ Done), а не только выделенные
- **FR-020**: При нажатии «Перенести на завтра», когда нет невыполненных задач, система ДОЛЖНА отображать сообщение «Нет задач для переноса»
- **FR-021**: Система ДОЛЖНА предотвращать повторную отправку запроса при быстром повторном нажатии кнопки «Перенести на завтра» (debounce)
- **FR-022**: Выделение задач ДОЛЖНО быть доступно с клавиатуры (Tab для навигации, Space/Enter для переключения чекбокса)
- **FR-023**: При массовом удалении всех задач в списке система ДОЛЖНА отображать пустое состояние (empty state)
- **FR-007**: Система ДОЛЖНА предоставлять возможность снятия выделения с отдельных задач перед выполнением массовой операции
- **FR-008**: Операция массового удаления ДОЛЖНА применяться ко всем выбранным задачам одновременно
- **FR-011**: После выполнения любой массовой операции выделение ДОЛЖНО сниматься со всех задач
- **FR-009**: Операция массового изменения даты ДОЛЖНА устанавливать одну и ту же дату (выбранную через пикер даты) для всех выбранных задач
- **FR-010**: Кнопка «Перенести на завтра» ДОЛЖНА переносить только невыполненные задачи, оставляя выполненные на своих текущих датах; кнопка ДОЛЖНА быть доступна всегда, а не только при просмотре определённого дня

### Ключевые сущности

- **Задача**: Основная сущность. Имеет статус (New, InProgress, Done), дату и содержимое. Подвергается массовым операциям
- **Выделение (Selection)**: Множество задач, выбранных пользователем для массовой операции путём ручного выделения каждой задачи (checkbox/клик, Tab+Space). Функция «Выбрать все» не предусмотрена. Выделение снимается после выполнения массовой операции
- **Массовая операция**: Действие, применяемое ко всем выделенным задачам одновременно (удаление, изменение даты) или ко всем невыполненным задачам (перенос на завтра). Операция «Перенести на завтра» не связана с выделением
- **Панель массовых действий**: Контейнер с кнопками массовых операций над выделением (удаление, изменение даты), который немедленно появляется при выделении первой задачи и немедленно скрывается при снятии последнего выделения
- **Кнопка «Перенести на завтра»**: Кнопка в Header, доступная всегда, действующая на все невыполненные задачи независимо от выделения

## Критерии успеха

### Измеримые результаты

- **SC-001**: Пользователь может выбрать несколько задач и выполнить массовую операцию (удаление или изменение даты) менее чем за 3 секунды от начала выбора до завершения операции (включая серверный ответ и обновление UI)
- **SC-002**: Операция «Перенести на завтра» выполняется одним нажатием кнопки без дополнительных шагов
- **SC-003**: Массовые операции обрабатывают все задачи корректно — сервер возвращает количество затронутых задач, и UI отражает это количество в обратной связи с пользователем
- **SC-004**: Все элементы управления массовыми операциями (чекбоксы выделения, панель действий, кнопка «Перенести на завтра») ДОЛЖНЫ быть видимыми и понятными без дополнительных инструкций

## Допущения

- Пользователи работают с задачами в контексте одного дня (основной вид — ежедневный список), однако операция «Перенести на завтра» действует глобально на все невыполненные задачи независимо от текущего вида
- «Несделанные задачи» — это задачи со статусом New (0) или InProgress (1), то есть все задачи со статусом, отличным от Done (2), независимо от их даты
- Перенос на «следующий день» означает установку даты на серверный UTC-день + 1 день (`DateTime.UtcNow.Date.AddDays(1)`)
- Отсутствие механизма отмены (undo/rollback) — осознанное продуктовое решение. Массовые операции применяются мгновенно без подтверждений и без отката
- После выполнения массовой операции выделение снимается со всех задач
- Задачи с разных дат могут быть выбраны одновременно для массового удаления, но массовое изменение даты установит для всех одну общую дату
- Выделение задач — только ручное (checkbox/клик по каждой задаче), без функции «Выбрать все»
- Операция «Перенести на завтра» не связана с механизмом выделения — она действует на все невыполненные задачи, а не только на выделенные
- Приложение не имеет системы авторизации — массовые операции доступны всем пользователям без ограничений по исполнителю
