## Clarifications

### Session 2026-05-17

- Q: Регистрозависимость имён исполнителей — "Иван" и "иван" — один или два разных? → A: Регистронезависимо — считается одним исполнителем, выбирается существующее написание.
- Q: Нужна ли валидация имени исполнителя (длина, пробелы, символы)? → A: Минимальная валидация — запретить пустые строки и строки из одних пробелов, макс. 100 символов.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Назначение исполнителя при создании и редактировании задачи (Priority: P1)

Пользователь может указать исполнителя как при создании новой задачи, так и при редактировании существующей. Исполнитель выбирается из выпадающего списка уже известных системе исполнителей или вводится вручную как новый. Исполнитель может отсутствовать (не назначен).

**Why this priority**: Назначение исполнителя — основная функция. Без неё остальные сценарии (отображение, фильтрация) теряют смысл.

**Independent Test**: Можно создать задачу с новым исполнителем, затем создать ещё одну задачу и убедиться, что введённый ранее исполнитель появился в выпадающем списке.

**Acceptance Scenarios**:

1. **Given** пользователь открыл форму создания задачи, **When** он начинает вводить имя исполнителя, **Then** появляется выпадающий список с ранее использованными исполнителями, отфильтрованный по введённому тексту.
2. **Given** пользователь вводит имя нового исполнителя, которого нет в списке, **When** он завершает создание задачи, **Then** новый исполнитель сохраняется и появляется в выпадающем списке при следующем использовании.
3. **Given** пользователь редактирует задачу, у которой уже есть исполнитель, **When** он открывает форму редактирования, **Then** текущий исполнитель отображается в поле выбора.
4. **Given** пользователь редактирует задачу, **When** он очищает поле исполнителя и сохраняет задачу, **Then** задача остаётся без исполнителя.
5. **Given** пользователь создаёт задачу, **When** он не указывает исполнителя, **Then** задача успешно создаётся без исполнителя.

---

### User Story 2 — Просмотр исполнителя на карточке задачи (Priority: P1)

На карточке задачи (на доске) отображается имя назначенного исполнителя. Если исполнитель не назначен, соответствующая область на карточке пуста или отсутствует.

**Why this priority**: Пользователи должны видеть, кто выполняет задачу, без необходимости открывать карточку. Это ключевая часть daily workflow.

**Independent Test**: Можно создать задачу с исполнителем и убедиться, что его имя видно на карточке на доске. Затем создать задачу без исполнителя — убедиться, что индикатор отсутствует.

**Acceptance Scenarios**:

1. **Given** на доске отображается задача с назначенным исполнителем, **When** пользователь смотрит на карточку задачи, **Then** он видит имя исполнителя.
2. **Given** на доске отображается задача без исполнителя, **When** пользователь смотрит на карточку задачи, **Then** область исполнителя пуста (не отображается).

---

### User Story 3 — Фильтрация задач по исполнителю (Priority: P2)

Пользователь может фильтровать задачи на доске по одному или нескольким исполнителям. Фильтр представляет собой выпадающий список с мультиселектом. Фильтр сохраняется при переключении между датами. Пользователь всегда видит, что фильтр активен.

**Why this priority**: Фильтрация — важный сценарий для работы с большой доской, но не является критической, если задач мало.

**Independent Test**: Можно выбрать двух исполнителей в фильтре, переключиться на другую дату и обратно — фильтр должен сохраниться.

**Acceptance Scenarios**:

1. **Given** на доске есть задачи разных исполнителей, **When** пользователь выбирает одного исполнителя в фильтре, **Then** на доске отображаются только задачи этого исполнителя.
2. **Given** пользователь выбрал нескольких исполнителей в фильтре, **When** он переключается на другую дату, **Then** фильтр остаётся активным с теми же выбранными исполнителями.
3. **Given** фильтр активен, **When** пользователь смотрит на интерфейс, **Then** он видит визуальный индикатор (цветовое выделение и текст), сообщающий, что фильтр применён.
4. **Given** фильтр активен, **When** пользователь нажимает кнопку сброса фильтра, **Then** фильтр очищается, и на доске отображаются все задачи.
5. **Given** фильтр активен и ни одна задача не соответствует выбранным исполнителям на текущую дату, **When** пользователь смотрит на доску, **Then** он видит пустую доску с сообщением о том, что активен фильтр.

---

### Edge Cases

- Пользователь ввёл исполнителя с именем, совпадающим с существующим по регистру — система находит существующего (регистронезависимое сравнение) и использует его, не создавая дубликат.
- Пользователь выбрал фильтр, затем удалил задачу, которая была единственной, соответствующей фильтру, — доска становится пустой, фильтр остаётся активным.
- Пользователь переключается между датами, фильтр активен, на одной из дат есть задачи под фильтр, на другой нет — поведение предсказуемо: задачи показываются там, где есть совпадения.
- Список исполнителей пуст (ни разу не назначали) — выпадающий список в фильтре и в форме задачи отображается пустым.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Пользователь MUST иметь возможность указать исполнителя при создании задачи.
- **FR-002**: Пользователь MUST иметь возможность изменить или удалить исполнителя при редактировании задачи.
- **FR-003**: Система MUST отображать имя исполнителя на карточке задачи на доске.
- **FR-004**: Поле выбора исполнителя MUST представлять собой комбобокс (выпадающий список + текстовый ввод), где отображаются все ранее использованные исполнители.
- **FR-005**: Система MUST автоматически добавлять нового исполнителя в общий список, если он был введён вручную и сохранён.
- **FR-006**: Система MUST предоставлять фильтр с мультиселектом по исполнителям на доске задач.
- **FR-007**: Фильтр MUST сохранять выбранных исполнителей при переключении между датами.
- **FR-008**: Система MUST визуально индицировать (цветом и текстом), что фильтр активен.
- **FR-009**: Пользователь MUST иметь возможность сбросить фильтр одним действием (одно нажатие).
- **FR-010**: Если после применения фильтра на текущую дату не осталось задач, система MUST отображать пустую доску с сообщением о том, что активен фильтр.
- **FR-011**: Исполнитель MUST быть опциональным — задача может существовать без исполнителя.

### Key Entities *(include if feature involves data)*

- **Задача (Task)**: Опционально содержит ссылку на исполнителя. Является центральной сущностью доски.
- **Исполнитель (Assignee)**: Строка (текстовое имя). Не привязан к системе аутентификации. Глобальный список всех когда-либо использованных исполнителей. У каждого исполнителя может быть множество задач.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь может назначить исполнителя новой задаче за 2 клика / 2 действия интерфейса.
- **SC-002**: Пользователь может изменить исполнителя существующей задачи за 2 клика / 2 действия интерфейса.
- **SC-003**: Пользователь может отфильтровать доску по конкретному исполнителю за 1 клик / 1 действие.
- **SC-004**: Пользователь может сбросить фильтр за 1 клик / 1 действие.
- **SC-005**: Индикатор активного фильтра заметен с первого взгляда (отличается цветом и содержит текст).
- **SC-006**: Фильтр надёжно сохраняется при переключении между датами (проверяется на 5 последовательных переключениях).
- **SC-007**: Новый исполнитель, введённый при создании задачи, доступен в выпадающем списке при следующем создании задачи без перезагрузки страницы.

## Assumptions

- Исполнители — это глобальный список, общий для всех задач на всех датах. Список формируется из всех существующих задач (не хранится отдельно). Валидация имени: запрещены пустые строки и строки из одних пробелов, макс. 100 символов. Регистронезависимое сравнение при поиске дубликатов.
- Список исполнителей не требует ручного управления (редактирования/удаления) — исполнители добавляются в список при назначении на задачу и удаляются оттуда только если удалена последняя задача с этим исполнителем.
- Порядок исполнителей в выпадающих списках: по алфавиту.
- При переключении между датами фильтр сохраняется в рамках текущей сессии.
- Аутентификация и авторизация не используются — исполнитель это просто текстовая строка.
